# Telegram 通知总览（域 × 形态 × 档位）

> 本文回答一个问题：**这个仓库现在会发哪些通知、各自属于什么形态、走什么档位**。
> 只描述种类与结构，**不登记逐条通知**（标题、字段、调用点随实现漂移）。
> 需要「现在到底有哪些通知」时现场枚举：

```bash
bash skills/telegram-notify-audit/scripts/list_notify.sh          # 全部发送点 / 标题 / 档位
bash skills/telegram-notify-audit/scripts/list_notify.sh openclaw # 只看某个域
```

- 版式与发送规则：[`telegram-notify.md`](telegram-notify.md)（规范，唯一真源）
- 域级出口与默认档位：[`telegram-notify-registry.md`](telegram-notify-registry.md)（台账）
- 三套实现与助手签名：`skills/telegram-notify-send/references/api-reference.md`

---

## 1. 两条正交视角

一条通知 =「某域 × 某形态」。二者不要混：

| 视角 | 回答什么 | 写在哪 |
|---|---|---|
| **形态**（规范 · 通知形态） | 这条消息长什么样：标题 / kv / 分节 / 条目 / 收尾区 | 规范第三章 |
| **域**（台账 · 域 → 出口 → 默认档位） | 从哪个出口发、发给哪个 bot、默认什么档位 | 台账第一章 |

同一形态可落在不同域（「结果通知」既用于备份也用于同步），同一域也会发多种形态（OpenClaw 域同时发网关就绪报告、生命周期播报和告警）。

## 2. 域清单（按发送点数排序）

数量来自 `list_notify.sh` 现场枚举，随实现变化；**只表示规模，不是固定断言**。

| 域 | 发送点量级 | 主力形态 | 档位分布 |
|---|---|---|---|
| OpenClaw Runner 与 AI 网关 | ~40 | 网关就绪报告、生命周期播报、告警 | 就绪 / 停止 / 倍率 / 用量普通；失败 / 风控 / 鉴权 / 残留 alert |
| OpenList 同步 | ~17 | 结果通知、清单明细、进度面板、复制即用命令块 | 成功 / 部分成功普通；同步失败 / 存储失效 / 中断 alert |
| 备份与任务 workflow | ~14 | 结果通知（三态 / 四态）、失败兜底 | 成功普通；中断 / 失败 alert；部分完成普通 |
| 测速三套 | ~7 | 结果通知 + TOP 清单 + 异常兜底 | 主报告普通；异常退出 / 信号终止 alert |
| Telegram 频道内容管线 | ~6 | 清单明细、结果通知 | 成功普通；失败 / 部分失败（需人工重试）alert |
| Emby | ~5 | 入口与凭据、启动 / 回退 / 播放 / 停止 | 停止按结论动态；其余普通 |
| 常驻服务与接力 | ~4 | 常驻服务报告、告警 | 故障 / 熔断 alert；恢复 / 正常普通 |
| Windows 入口 | ~2 | 入口与凭据（pwsh） | 普通 |

> 进度面板、`sendDocument` 日志附件、视频 caption 直连 bot，**不参与档位路由**（台账 · 域 → 出口 → 默认档位）。

## 3. 形态清单

| 形态 | 典型场景 | 固定骨架 | 档位倾向 |
|---|---|---|---|
| 结果通知 | 备份 / 同步 / 测速 / 分割收尾 | 标题（状态 emoji）→ 关键 kv → 明细分节 → 收尾区 | 随结论 |
| 清单明细 | 已上传文件、失败清单、账号池 | 先按状态分组（组头 + 计数），再树形列出 | 随所属通知 |
| 复制即用命令块 | force_sync、还原入口 | 分节 → 说明段（▸ 描述）→ `<pre>` 命令 | 随所属通知 |
| 失败与异常兜底 | 未捕获异常、信号终止、崩溃 | 极简：标题 + 原因 + 收尾区 | alert |
| 告警通知 | 归档失败、存储失效、网关启动失败 | 对象机器值 + 结论裸文本 + `<pre>` 原始输出 | alert |
| 入口与凭据 | SSH / RDP / 出口网络、改密回执 | 按套分节，整节同为 `标签：<code>值</code>` | 普通（入口故障另发 alert） |
| 网关就绪报告 | AI 网关起服后的可用性播报 | 先回答「能不能用」，再列数据段；缺失就说缺失 | 普通 |
| 进度面板 | openlist 同步进度原地刷新 | 状态 kv + 计数行 + 五组任务列表 + 批次历史 + 收尾区 | 不参与档位（直连主 bot） |
| 生命周期播报 | 交接、停机倒计时、新 run 启动、停止汇总 | 标题写阶段，kv 说「是否可用 / 还要多久」 | 普通；停机倒计时 alert |
| 常驻服务报告 | 健康看门狗、dropbox 挂载守卫 | 标题 + kv + 说明段 + `🕒` 报告时刻 | 故障 alert；恢复普通 |
| 带动作行 | 播放通知「▶ 打开直链」 | 正文与动作行之间补一个空行 | 普通 |
| 媒体 caption | 随视频发出的说明 / 错误日志附件 | 三行（文件名 / 大小 / 时间）或单行 `📁 任务 · 错误日志` | 不参与档位（媒体固有例外） |

形态的完整规则与示例见规范第三章；本文不复制示例，避免两处维护。

## 4. 档位判定（摘要）

唯一口径在规范 · 档位判定。这里只给速记：

| 图标 | 档位 | 判据 |
|---|---|---|
| ❌ ⛔ 🆘 🔴 🟠 🧯 🚫 | alert | 不可用 / 需人修 / 需当场动手 |
| ⚠️ | 视分支 | 已自动降级且服务可用 → 普通；必须人工处理 → alert（调用点写注释说明走了哪侧） |
| 🟡 🟢 ✅ | 普通 | 服务在、等即可 / 常态运行 |

- **不设域级例外**：要偏离必须先改规范 · 档位判定，台账只记录现状。
- alert 档由调用点在**分支里显式传** `_tier="alert"`，不按标题字符串分诊；凭据缺失由发送层失败留痕，调用点不加静默守卫。
- 两档 × 两侧，只用 @FuckSaberBot（普通）与 @SaberFuckBot（alert），见规范 · 全库 bot 分工。

## 5. 怎么维护这组文档

| 变化 | 要改什么 |
|---|---|
| 新增 / 改名 / 下线单条通知 | **不改文档**，现场枚举即可 |
| 某域换出口、默认档位变化 | 改台账 |
| 新增形态、改版式、改发送规则 | 先改规范，再同步三套实现与核对基线 |
| 域的常见形态组合明显变化 | 改本文第二章 |

规范只写版式与规则，台账只写域与档位，本文只写种类与结构——同一句话不要出现在两份文件里。
